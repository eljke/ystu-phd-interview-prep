# YSTU PhD Interview Prep · 1.2.2

Приложение для самостоятельной и парной подготовки к устному вступительному собеседованию в аспирантуру ЯГТУ по специальности **1.2.2 «Математическое моделирование, численные методы и комплексы программ»**.

## Что есть в приложении

- все 43 пункта официальной программы: 16 тем моделирования, 10 тем численных методов и 17 тем комплексов программ;
- простые конспекты, ключевые мысли, короткие примеры и источники без лишней академичности;
- банк из 200+ заданий без повторения одного тезиса в наборе: один или несколько ответов, сопоставление, порядок, короткий термин и самостоятельное объяснение;
- по одной теме встречаются разные форматы, а случайная выдача чаще возвращает слабые темы и не повторяет только что показанные вопросы;
- короткие термины проверяются без учёта регистра, `ё/е`, пунктуации и лишних пробелов; длинные ответы не оцениваются сравнением строк;
- личная статистика в целом и по трём разделам;
- соло-режим и микротурнир с двух устройств: оба получают одинаковые вопросы, чужой ответ и ключ скрыты до ответа второго игрока;
- вход через GitHub только для логинов из whitelist, управление доступом из админки;
- синхронизация прогресса через Supabase с локальной очередью при временном отсутствии сети;
- PWA и автоматическая публикация на GitHub Pages.

Запись голоса и отдельная устная сессия оставлены в roadmap. Сейчас акцент на тестах, активном вспоминании и взаимной проверке.

## Локальный запуск

Требуются Node.js 22 и Docker Desktop.

```bash
npm ci
npm run supabase:start
npm run supabase:reset
```

Скопируйте `.env.example` в `.env.local` и возьмите локальные URL и publishable key из вывода `supabase status`. Затем:

```bash
npm run dev
```

Локально приложение допускает работу без Supabase-конфига, чтобы контент и интерфейс можно было разрабатывать офлайн. Production без облачного конфига работает в режиме fail-closed: показывает служебный экран и не открывает материалы без whitelist.

## Проверки

```bash
npm run verify          # типы, lint, аудит контента, unit/component-тесты и build
npm run supabase:reset  # миграции и seed на чистой локальной БД
npm run test:rls        # SQL-тесты whitelist, RLS и запечатанного турнира
npm run e2e:chromium    # пользовательские сценарии в Chromium
```

## Production Supabase

1. Создайте проект Supabase и свяжите CLI: `npx supabase login`, `npx supabase link --project-ref <ref>`.
2. Примените схему: `npx supabase db push`.
3. Разверните админ-функцию: `npx supabase functions deploy manage-access`.
4. В Supabase Auth включите GitHub provider. Callback URL для GitHub OAuth App: `https://<ref>.supabase.co/auth/v1/callback`.
5. В URL Configuration добавьте `https://eljke.github.io/ystu-phd-interview-prep/**` в Redirect URLs.
6. Один раз добавьте первоначального администратора через SQL Editor:

```sql
insert into public.access_entries (github_user_id, github_login, role)
values (73737815, 'eljke', 'admin')
on conflict (github_user_id) do update
set github_login = excluded.github_login,
    role = 'admin',
    active = true,
    updated_at = now();
```

После этого остальные логины добавляются на экране «Доступ». Проверка выполняется по неизменяемому GitHub ID; логин хранится для отображения и может обновляться.

## GitHub Pages

В `Settings → Secrets and variables → Actions → Variables` задайте:

- `VITE_SUPABASE_URL` — Project URL;
- `VITE_SUPABASE_PUBLISHABLE_KEY` — publishable key проекта.

В `Settings → Pages` выберите source `GitHub Actions`. Каждый push в `master` проверяет заданный production-конфиг, выполняет весь frontend verification и публикует `dist`. Если переменные ещё не заданы, публикуется только закрытый служебный экран. CI отдельно поднимает чистый локальный Supabase и запускает SQL/RLS-тесты.

## Данные и источник

Персональные данные и прогресс доступны только авторизованному пользователю; пара видит только совместные турнирные данные. До ответа обоих серверная RPC не возвращает чужой ответ или ключ. Локальная IndexedDB используется как кэш и очередь синхронизации.

Копия официальной программы лежит в `public/source/ystu-programme-1.2.2-2026.pdf`. Нумерация и формулировки тем сохранены, включая раздельные пункты 3.7 и 3.8.
