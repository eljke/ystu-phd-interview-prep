# Сайт подготовки к вступительному собеседованию в аспирантуру ЯГТУ

**Дата:** 2026-08-01
**Статус:** утверждён пользователем; план реализации подготовлен
**Исходный документ:** `Программа_1.2.2_2026(2).pdf` — программа вступительного испытания по научной специальности 1.2.2 «Математическое моделирование, численные методы и комплексы программ».

## 1. Цель продукта

Создать статическое интерактивное веб-приложение для подготовки двух человек к устному вступительному собеседованию в аспирантуру ЯГТУ. Приложение должно помочь быстро сформировать связный поверхностный ответ по каждому пункту программы, чтобы поступающий мог уверенно назвать определение, ключевые элементы, область применения и простой пример, не углубляясь в доказательства и узкоспециализированные детали.

Приложение должно:

- включать все 43 нумерованных пункта программы без добавления новых экзаменационных тем;
- сохранять исходную нумерацию и формулировки;
- предоставлять все темы сразу, без последовательной разблокировки;
- поддерживать неравномерную нагрузку: длинные занятия в свободные дни, короткие занятия или перерывы в другие дни;
- сочетать краткие конспекты, мини-тесты, устные ответы и взаимную проверку;
- работать локально и после первой загрузки — без подключения к сети;
- размещаться на GitHub Pages;
- запускаться и разрабатываться в IntelliJ IDEA;
- хранить прогресс двух участников локально и быть готовым к последующему подключению Supabase.

## 2. Официальный контекст испытания

По программе ЯГТУ вступительное испытание проводится индивидуально в форме устного собеседования по темам приложения № 1. Минимальный результат для успешного прохождения и участия в конкурсе — 70 баллов, максимальный — 100 баллов.

В приложении будет отдельный экран «О программе», где воспроизводятся:

- назначение испытания;
- устный индивидуальный формат;
- порог 70 из 100;
- официальные диапазоны оценивания 81–100, 61–80, 41–60, 21–40, 1–20 и 0 баллов;
- рекомендованная литература и интернет-ресурсы из PDF;
- ссылка на исходный PDF, если файл включён в публичный репозиторий с разрешения владельца.

Внутренняя метрика готовности приложения не называется официальным экзаменационным баллом. Она предназначена только для выбора слабых тем и не имитирует решение приёмной комиссии.

## 3. Не-цели первой версии

Первая версия не включает:

- регистрацию и облачную авторизацию;
- синхронизацию в реальном времени между устройствами;
- запись или распознавание речи;
- генерацию новых вопросов с помощью ИИ;
- открытый пользовательский редактор учебного контента;
- соревнование, лидерборд или штрафы за пропуски;
- углублённый математический курс, доказательства и большие вычислительные задачи;
- автоматическое утверждение спорных или неоднозначных формулировок исходной программы.

## 4. Основания проектных решений

### 4.1. Активное воспроизведение

Основной сценарий сначала предлагает попытаться ответить, а затем открыть краткий каркас и расширенное объяснение. Это соответствует эффекту тестирования: попытка воспроизвести материал улучшает последующее сохранение знаний по сравнению с одним повторным чтением.

### 4.2. Распределённая практика без жёсткого календаря

Система рассчитывает приоритет повторения, но не создаёт «долгов» и не блокирует свободный выбор. Исследования распределённой практики поддерживают повторение с интервалами, однако оптимальный интервал зависит от желаемого срока удержания; поэтому в продукте рекомендации остаются мягкими.

### 4.3. Взаимное объяснение

Парный режим строится вокруг индивидуального ответа, обсуждения и оценки по чек-листу. Данные по Peer Instruction показывают пользу структурированного обсуждения концептуальных вопросов и совместного рассуждения.

### 4.4. Технические основания

Vite собирает приложение в статический каталог `dist`; официальный сценарий публикации на GitHub Pages использует корректный `base` и GitHub Actions. Dexie предоставляет типизированную оболочку над браузерной IndexedDB и React-интеграцию, подходящую для локального offline-first хранения.

## 6. Архитектура

Приложение представляет собой статическое SPA. Учебный контент включается в сборку, а пользовательские данные хранятся отдельно в IndexedDB.

```text
src/
├── app/                    # маршрутизация, провайдеры, конфигурация
├── pages/                  # композиция экранов
├── features/
│   ├── topics/             # каталог и просмотр темы
│   ├── study-session/      # произвольная учебная сессия
│   ├── quizzes/            # мини-тесты
│   ├── oral-exam/          # устная попытка с таймером
│   ├── pair-session/       # взаимный опрос
│   ├── review/             # мягкие рекомендации
│   ├── progress/           # статистика участника и пары
│   └── backup/             # экспорт, сравнение и импорт
├── entities/               # доменные типы и чистая логика
├── repositories/           # интерфейсы доступа к данным
├── storage/
│   └── dexie/              # локальная реализация репозиториев
├── content/                # 43 темы, тесты и источники
└── shared/                 # UI, хуки, утилиты, стили
```

### 6.1. Границы модулей

- `content` содержит только версионируемый учебный материал и не знает о пользователях.
- `entities` содержит типы, формулы готовности, планировщик повторений и правила объединения данных.
- `repositories` определяет контракты хранения.
- `storage/dexie` реализует эти контракты для IndexedDB.
- `features` использует только интерфейсы репозиториев, а не Dexie напрямую.
- `pages` собирает функции в пользовательские сценарии.

Такое разделение позволит позднее добавить `SupabaseProgressRepository` без изменения экранов и алгоритмов обучения.

## 7. Модель учебного контента

```ts
export interface Topic {
  id: string;
  code: string;
  section: TopicSection;
  originalText: string;
  shortAnswer: string;
  extendedAnswer: string;
  keyPoints: KeyPoint[];
  formulas: FormulaBlock[];
  example?: string;
  commonMistakes: string[];
  oralChecklist: OralCriterion[];
  quiz: QuizQuestion[];
  sources: TopicSource[];
}
```

### 7.1. Слои одной темы

Каждая тема содержит:

1. исходную формулировку из программы;
2. скрытую до попытки ответа шпаргалку;
3. ответ на 30–60 секунд;
4. ответ на 1–2 минуты;
5. ключевые определения, классификации и этапы;
6. только необходимые для устного ответа формулы и схемы;
7. один компактный пример;
8. типичные ошибки и смешиваемые понятия;
9. критерии устного ответа;
10. мини-тест по содержанию этой темы;
11. 2–4 источника с указанием поддерживаемых тезисов.

### 7.2. Границы содержания

- `originalText` воспроизводит исходный пункт программы.
- Объяснение раскрывает только понятия, перечисленные в этом пункте.
- Дополнительные сведения допустимы как пояснение, пример или связка, но не оформляются как новые экзаменационные темы.
- Материал ориентирован на поверхностное понимание и связный устный ответ.
- Формулы приводятся только там, где без них ответ будет неполным или расплывчатым.
- В тестах нельзя проверять сведения, отсутствующие в конспекте темы.

### 7.3. Особенность пунктов 3.7 и 3.8

В исходном PDF фраза визуально разделена нумерацией:

- `3.7. Прикладное программное обеспечение научных исследований. Формы`
- `3.8. представления комплексов прикладных программ: библиотека, пакет прикладных программ, диалоговая система.`

Приложение сохраняет оба номера как отдельные доступные пункты, потому что программа содержит 17 пунктов раздела 3. В интерфейсе рядом отображается нейтральная пометка, что формулировка выглядит как единое предложение, разделённое в исходном документе. Приложение не исправляет и не перенумеровывает программу без подтверждения ЯГТУ.

## 8. Полный перечень тем

### 8.1. Математическое моделирование — 16 тем

1. **1.1.** Определение понятия «модель». Функции моделей при проведении научных исследований. Особенности и области применения математического моделирования, вычислительного и натурного эксперимента.
2. **1.2.** Виды математических моделей. Параметры математической модели. Основные этапы создания математической модели.
3. **1.3.** Прямые и обратные задачи. Качественные и аналитические методы исследования математических моделей.
4. **1.4.** Экспериментально-статистические методы моделирования. Функции распределения непрерывных случайных величин и их параметры. Оценки параметров функций распределения по экспериментальным данным. Статистические гипотезы.
5. **1.5.** Метод дисперсионного анализа. Однофакторный и двухфакторный дисперсионный анализ.
6. **1.6.** Уравнение регрессии и регрессионный анализ. Вычисление коэффициентов уравнения регрессии методом наименьших квадратов. Оценка значимости коэффициентов регрессии и проверка адекватности математической модели.
7. **1.7.** Планирование экспериментов при регрессионном анализе. Планы 1-го и 2-го порядков. Последовательные методы планирования эксперимента.
8. **1.8.** Постановка задачи оптимизации. Аналитические методы определения безусловного экстремума.
9. **1.9.** Решение задач условной оптимизации при ограничениях вида равенств методом неопределенных множителей Лагранжа.
10. **1.10.** Моделирование детерминированных динамических систем с сосредоточенными параметрами. Постановка задачи, условия существования и единственности решения.
11. **1.11.** Качественное исследование устойчивости одномерных динамических моделей. Бифуркация в одномерной модели. Типы катастроф.
12. **1.12.** Типы уравнений, применяемых для моделирования детерминированных систем с распределенными параметрами. Условия, необходимые для нахождения единственного решения дифференциального уравнения в частных производных.
13. **1.13.** Понятие имитационной модели. Области применения и цели имитационного моделирования. Составляющие имитационной модели.
14. **1.14.** Марковские процессы. Марковская цепь. Вычисление вероятностей состояний марковской цепи с помощью матрицы переходных вероятностей.
15. **1.15.** Системы массового обслуживания. Показатели эффективности системы массового обслуживания. Плотность распределения потоков заявок.
16. **1.16.** Распределённые системы имитационного моделирования. Управление временем в распределённых системах имитации.

2. учебник или открытый университетский курс;
3. рецензируемая статья или академическая публикация;
4. рекомендованная программой литература;
5. надёжный справочный источник, если первичный источник слишком сложен для целевого уровня.

У каждого источника хранится поле `supports`, перечисляющее конкретные тезисы темы. Ссылка не считается достаточной сама по себе: редактор контента должен указать, что именно она подтверждает.

## 10. Пользовательские данные

```ts
export interface TopicProgress {
  profileId: string;
  topicId: string;
  status: TopicStatus;
  confidence: number;
  viewedKeyPointIds: string[];
  quizScore?: number;
  selfAssessment?: number;
  partnerAssessment?: number;
  nextReviewAt?: string;
  updatedAt: string;

```

### 10.1. Таблицы Dexie

- `profiles` — два локальных профиля;
- `topicProgress` — текущее состояние темы у участника;
- `quizAttempts` — попытки тестов и ответы;
- `oralAttempts` — устные попытки;
- `partnerAssessments` — оценки партнёра;
- `studySessions` — история занятий;
- `reviewQueue` — вычисленные рекомендации;
- `achievements` — ненавязчивые достижения;
- `settings` — таймеры, интерфейс, активный профиль;
- `meta` — версия схемы, версия контента, сведения о миграциях.

### 10.2. Репозиторный слой

export interface ProgressRepository {

## 11. Основные экраны

### 11.1. Первичный запуск

- создание двух профилей или одного с возможностью добавить второго;
- краткое объяснение локального хранения;
- предложение сразу экспортировать резервную копию после настройки;
- выбор длительности устного ответа по умолчанию;
- переход к полностью открытому каталогу.

### 11.2. Главная

- готовность каждого участника;
- готовность пары;
- быстрые действия: «Выбрать темы», «Быстрый тест», «Устный ответ», «Парная сессия»;
- рекомендуемые повторы без метки просрочки;
- недавно изученные темы;
- слабые темы пары;
- история последних сессий.

### 11.3. Каталог

- все темы доступны сразу;
- поиск по номеру и тексту;
- фильтр по разделу, статусу, участнику и рекомендации;
- сортировка по номеру, уверенности, последнему повторению и готовности пары;
- мультивыбор тем для произвольной сессии;
- сохранение набора тем;
- отображение исходной формулировки без открытия карточки.

### 11.4. Страница темы

Порядок блоков:

1. номер, раздел, исходная формулировка;
2. кнопка «Попробовать ответить»;
3. таймер по желанию;
4. раскрытие ответа на 30–60 секунд;
5. раскрытие ответа на 1–2 минуты;
6. ключевые понятия;
7. формулы или схема;
8. пример;
9. типичные ошибки;
10. источники с привязкой к тезисам;
11. запуск теста или устной попытки;
12. отметки прогресса.

### 11.5. Мини-тест

Поддерживаемые типы:

- один правильный вариант;
- несколько правильных вариантов;
- сопоставление;
- правильная последовательность;
- заполнение пропуска термином из темы.

После ответа показываются правильный вариант, объяснение и ссылка на соответствующий фрагмент темы. Тест не вводит новый материал.

### 11.6. Устный режим

```text
выбор темы
→ 20 секунд на подготовку
→ 1–2 минуты на ответ
→ раскрытие эталонного каркаса
→ самооценка
→ при парной сессии оценка партнёра
```

Таймер настраивается или отключается. Для устойчивой работы при сворачивании вкладки время вычисляется по временным меткам, а не только по интервалам JavaScript.

### 11.7. Парная сессия

- выбор отвечающего и проверяющего;
- автоматическая смена ролей после каждого вопроса по настройке;
- режимы: случайные темы, слабые темы отвечающего, слабые темы пары, выбранный набор, пробное собеседование;
- сначала самостоятельный ответ без подсказки;
- затем оценка по чек-листу;
- после оценки — эталонный каркас и обсуждение;
- отметка «объяснил партнёру».

### 11.8. Прогресс пары

Главная кооперативная метрика — доля тем, которые могут объяснить оба участника. Для темы используется минимум индивидуальной готовности, а не среднее значение.

### 11.9. О программе и источниках

- официальное описание устного вступительного испытания;
- порог и диапазоны оценивания из первой страницы программы;
- пояснение, что готовность в приложении не является прогнозом официального балла;
- полный список рекомендованной литературы из четвёртой страницы;
- список использованных по темам дополнительных источников;
- версия и дата учебного контента.

### 11.10. Резервное копирование

- экспорт полного снимка пары в JSON;
- версия формата и контрольная сумма;
- импорт с проверкой Zod;
- предварительный просмотр различий;
- режимы «объединить» и «заменить после резервной копии»;
- при объединении — сравнение сущностей по `updatedAt`, а при конфликте одинаковой даты и разных данных — ручной выбор;
- автоматическая резервная копия текущей базы перед заменой.

## 12. Гибкие рекомендации

У приложения нет обязательной дневной нормы и понятия «просрочено». Приоритет темы рассчитывается как функция:

```text
низкая точность тестов
+ низкая самооценка
+ низкая оценка партнёра
+ время с последней попытки
+ незакрытые ключевые пункты
+ ручная отметка «повторить»
```

Пользователь может игнорировать, откладывать или очищать рекомендации. Длинная сессия не создаёт искусственного ограничения на число тем.

## 13. Готовность и статусы

### 13.1. Индивидуальные статусы

```text
Не начата → Изучаю → Могу ответить → Закреплена
                    ↘ Нужно повторить
```

`Могу ответить` требует:

- просмотра основного материала;
- хотя бы одной тестовой попытки;
- хотя бы одной устной попытки;
- отсутствия критических пропусков по чек-листу.

`Закреплена` требует нескольких успешных попыток в разные календарные дни. Один высокий результат не переводит тему сразу в закреплённую.

### 13.2. Расчёт готовности

```ts
export interface TopicMastery {
  coverage: number;
  quizAccuracy: number;
  selfConfidence: number;
  oralScore: number;
  partnerScore?: number;
  lastReviewedAt?: string;
}
```

Весовые коэффициенты задаются в одном чистом модуле и покрываются тестами. На первом релизе коэффициенты фиксированы и не редактируются пользователем.

### 13.3. Готовность пары

```text
готовность пары по теме = min(готовность участника A, готовность участника B)
```

Так итоговый показатель не скрывает слабое место одного участника.

## 14. Геймификация

Допустимы только механики, поддерживающие подготовку:

- очки за первую самостоятельную устную попытку;
- достижения за охват раздела;
- отметка «объяснил партнёру»;
- совместная шкала готовности;
- история завершённых сессий;
- мягкие milestone-сообщения без конфетти на каждом действии.

Не используются:

- ежедневные серии;
- штрафы;
- публичный рейтинг;
- бесконечные награды за клики;
- блокировка материалов очками.

## 15. Визуальное направление и доступность

Интерфейс — спокойный современный академический инструмент, а не яркая мобильная игра.

- светлая и тёмная темы;
- адаптивность от телефона до широкого экрана;
- крупные читаемые карточки и короткие строки;
- устойчивый визуальный код трёх разделов, не зависящий только от цвета;
- видимый фокус клавиатуры;
- полная работа основных сценариев с клавиатуры;
- уважение `prefers-reduced-motion`;
- контраст не ниже WCAG AA;
- семантические заголовки и доступные подписи контролов;
- математические формулы имеют текстовое пояснение;
- тесты не сообщают правильность только цветом.

## 16. Offline и обновления

- приложение кэширует shell и статический учебный контент;
- пользовательский прогресс остаётся в IndexedDB и не помещается в service worker cache;
- новая версия приложения загружается в фоне;
- пользователь получает предложение обновиться после завершения текущей попытки;
- версия контента хранится отдельно от версии схемы базы;
- миграция не удаляет попытки и оценки;
- при критической ошибке миграции приложение предлагает экспортировать сырые данные и перейти в режим чтения.

## 17. Обработка ошибок

- недоступная IndexedDB: понятный экран, временный режим без сохранения и инструкция по разрешению хранилища;
- превышение квоты: предложение экспортировать резервную копию и очистить старую историю попыток без удаления итогового прогресса;
- повреждённый импорт: отказ до изменения базы с перечнем ошибок;
- конфликт импорта: явный diff и ручной выбор;
- неработающая внешняя ссылка: учебный материал остаётся доступен, источник помечается как недоступный только после явной проверки пользователя;
- ошибка одного виджета: error boundary на уровне функции, а не падение всего приложения;
- некорректный контент сборки: production build завершается с ошибкой.

## 18. Контроль качества контента

Автоматический аудит проверяет:

- ровно 43 темы;
- распределение 16 / 10 / 17;
- уникальность кодов и идентификаторов;
- непрерывность ожидаемой нумерации;
- наличие исходной формулировки;
- наличие краткого и расширенного ответа;
- хотя бы один ключевой пункт;
- хотя бы один вопрос;
- объяснение каждого правильного ответа;
- связь вопроса с идентификаторами тезисов темы;
- 2–4 источника;
- непустой `supports` у каждого источника;
- отсутствие неизвестных типов формул и вопросов;
- валидность внутренних ссылок на фрагменты темы.

Экран `/content-audit` показывает результаты аудита. Он не отображается в пользовательском меню, но доступен по прямому маршруту в production для проверки опубликованной версии.

## 20. GitHub Pages и IntelliJ IDEA

- package manager: npm;
- минимальная поддерживаемая версия Node.js фиксируется в `.nvmrc` и `package.json#engines`;

## 21. Будущее подключение Supabase

После локальной версии можно добавить:

- идентификатор пары и приглашение второго участника;

## 22. Критерии приёмки первой версии

Версия считается готовой, когда:

1. в каталоге присутствуют все 43 пункта и проходят проверки распределения 16 / 10 / 17;
2. исходные формулировки доступны без регистрации;
3. каждый пункт содержит оба уровня ответа, тест, устный чек-лист и источники;
4. все темы доступны сразу;
5. пользователь может создать двух участников;
6. индивидуальный и парный прогресс сохраняется после перезагрузки;
7. работает произвольная, тестовая, устная и парная сессия;
8. рекомендации не блокируют выбор и не штрафуют за пропуски;
9. экспорт и импорт проходят сквозной тест;
10. production build открывается на GitHub Pages под URL репозитория;
11. приложение повторно открывается offline после первого посещения;
12. линтинг, типы, тесты, аудит контента и сборка проходят в CI;
13. README позволяет запустить проект в IntelliJ IDEA без дополнительных скрытых шагов;
14. экран «О программе» корректно показывает формат, порог, диапазоны оценивания и литературу из PDF, не выдавая внутреннюю готовность за официальный балл.
